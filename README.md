# Bubu & Dudu

Local co-op 2D adventure for two players on one screen (Godot 4.7, GDScript, Compatibility renderer).
Four chapters, 56 rooms, about 6 hours for a first-time pair. Targets: Windows and Web.

> No spoilers here: layouts, solutions and story live in `data/` and `scenes/rooms/`.
> Player 1 plays blind, so don't open those files if you're Player 1.

## Controls

| Pad | Action |
| --- | --- |
| Left stick | Move (up/down on vines) |
| A | Jump (hold for higher) |
| B | Interact / pick up / put down |
| Y tap | Piggyback on / off, hug in cozy spots |
| Y hold | Call the partner over (where allowed) |
| Start | Pause |

Pad 0 is Bubu (P1) and pad 1 is Dudu (P2). Keyboard fallback: P1 uses `A D W S`, `Space`, `E`, `Q`, `Esc`.
P2 uses the arrow keys, `Enter`, `.`, `/` and `Backspace`.

## Layout

```
scenes/core/        Game (room loader, transitions, pause), Room, GameState (save), Sfx (procedural audio)
scenes/characters/  BasePlayer, Bubu, Dudu, CharacterRig (animated vector cut-out), HeartBalloon
art/characters/     panda and bear parts (SVG) generated by tools/gen_sprites.py
art/illustrations/  vector pack illustrations used by the menu and credits
scenes/components/  reusable room pieces (plates, gates, crates, seesaw, wind, vines, ...)
scenes/ui/          main menu, dialogue box, HUD, pause, album, options, credits
scenes/rooms/chN/   generated rooms (do not edit by hand)
data/               chapters.json, memories.json, dialogue/*.json, credits.json
tools/              room generator (roomkit.py, beats.py, chapters.py, gen_rooms.py), gen_project.py
tests/              headless test runner, room-solving bot, per-room solutions
```

## Character art

```bash
python -I tools/gen_sprites.py [path/to/vector_pack_folder]
```

Cuts the vector pack's panda and bear into parts (head, ears, face expressions, body, arms, feet)
in `art/characters/`. `CharacterRig.gd` animates them in code: idle, walk, jump, fall, climb, ride,
carry, balloon, call wave and hug. With a pack folder it also copies the illustrations into
`art/illustrations/`, re-centering the character groups that the original files place at the left
edge. The pack says it is fan-style art, not official: check the rights before any public release.
The same script writes the dialogue portraits, the window icon and the UI icons in `art/ui/` (heart,
next arrow, toggles, slider knob), so the UI uses no font glyphs or emoji that a web font might lack.

## UI

`scenes/ui/UiTheme.gd` holds the color tokens (each text color is checked for at least 4.5:1 contrast
on the panel color), the 18 px text floor and the button, slider and toggle states (hover, focus and
pressed all look different). Options include "Testo grande" (reading text ×1.28) and "Riduci
movimento" (menu drift off, gentler squash, tilt and shake). The dialogue box goes to the top or the
bottom of the screen, whichever hides fewer of the two characters.
Fonts are Nunito (reading) and Fredoka (headings) from Google Fonts, both under the SIL Open
Font License (`art/fonts/OFL_*.txt`).

## Animated GIFs

```bash
godot --fixed-fps 60 --path . --script res://tests/run.gd -- gifs
python -I tools/make_gif.py
```

Records looping clips of the two characters (wave, hug, jump, walk, piggyback) from the in-game rig
and encodes them into `media/gifs/` (480x360, 20 fps, pure-Python encoder, no Pillow needed). The
recording needs a window, so run it without `--headless`. `media/` is not imported or exported.

## Regenerate rooms

```bash
python -I tools/gen_rooms.py
```

This rewrites `scenes/rooms/ch*/`, `tests/solutions/` and `data/chapters.json`. It also checks that every
dialogue and memory id exists and prints the duration estimate. `python -I tools/gen_rooms.py dev`
writes one whitebox room per puzzle beat.

## Tests

```bash
godot --headless --path . --import
godot --headless --fixed-fps 60 --path . --script res://tests/run.gd
```

Suites are `smoke`, `components`, `flow`, `rooms` and `chaos`. A bot plays every room from start to exit;
`chaos` mashes seeded random input in every room and checks nobody leaves the room or gets stuck in a wall.
Any engine error during a suite fails it.
Pass suite names after `--` to run only some of them, e.g. `-- rooms c2_r04`, `-- rooms dev`, `-- flow`
or `-- chaos c3_r02 -s=60` (seconds per room).
`-- shots c1_r01 menu ui` saves screenshots to `user://shots/`. It needs a window, so run it without
`--headless`.

## Export

`export_presets.cfg` has a "Windows Desktop" preset (`build/windows/`) and a "Web" preset (`build/web/`,
threads off). Both need the Godot 4.7 export templates (Editor → Manage Export Templates, or the
official `Godot_v4.7-stable_export_templates.tpz` from the GitHub release).

```bash
godot --headless --path . --export-release "Windows Desktop" build/windows/BubuDudu.exe
godot --headless --path . --export-release "Web" build/web/index.html
```

The Windows build is a single exe (data embedded). The web build is single-threaded, so any static
server works without special headers, e.g. `python -m http.server --directory build/web`. On web, each
pad only shows up after you press one of its buttons.
